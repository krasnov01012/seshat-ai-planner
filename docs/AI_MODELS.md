# Выбор AI-модели: замеры на русском языке

Все цифры ниже получены реальными запросами к NVIDIA NIM
(`https://integrate.api.nvidia.com/v1`) 2026-08-03, а не взяты из документации.
Скрипты воспроизведения — в [../tools/](../tools/).

## Итог

| Роль | Модель | Почему |
|---|---|---|
| **Основная** | `nvidia/nemotron-3-super-120b-a12b` | Лучшая точность **и** лучшая скорость: 27/29, медиана 4.0 с. Ноль ошибок сети за оба раунда. Поддерживает все три режима structured output |
| **Запасная** | `nvidia/nvidia-nemotron-nano-9b-v2` | Та же точность 27/29 при 5.8 с. Заметно терпимее к параллельным запросам (20/24 против 10/24), поэтому годится, когда основная отдаёт 429 |
| **Вторая запасная** | `z-ai/glm-5.2` | 27/29, 6.7 с. Единственная, кто верно определил тип «рутина». Но самый жёсткий лимит: 429 уже на последовательных запросах |

Порядок вызова: основная → при 429/5xx три ретрая с экспоненциальной задержкой →
запасная → вторая запасная → отказ с просьбой повторить позже.

## Раунд 1 — точность разбора русских фраз

10 фраз: разовое событие, ежедневная рутина, рутина по дням недели, задача
с дедлайном, фокус-сессия с длительностью, событие с двумя напоминаниями,
отложить в контексте напоминания, перенос, неоднозначная дата, «я уже сделал».
Проверялись отдельные поля: intent, тип, дата, время, длительность, повторение,

### Два вывода, которые изменили архитектуру

**1. Тип записи нельзя доверять модели.**
На фразе «По понедельникам, средам и пятницам тренировка в 19:00» **все** модели
верно извлекли повторение `weekly / mon, wed, fri / 19:00`, но четыре из шести
назвали запись `event` вместо `routine`. Слоты извлекаются хорошо, классификация —
плохо. Отсюда правило этапа 2.5 первого роадмапа: **модель извлекает поля,
тип выводит код** по наличию `rrule` / `due` / `start`.

**2. Подтверждение перед сохранением — не вежливость, а необходимость.**
На «В следующую пятницу утром подать документы» (от понедельника 3 августа) ответы
разошлись: 7 августа (пятница этой недели), **8 августа — суббота**, и `null`.
Молча сохранять такое нельзя. Модель обязана возвращать `needs_clarification`,
и при `true` или при `confidence < 0.7` бот переспрашивает.

## Раунд 2 — structured output

Проверялись три способа получить гарантированный JSON.

| Модель | `json_schema` | `json_object` | `nvext.guided_json` | Среднее |
|---|---|---|---|---|
| `nvidia/nemotron-3-super-120b-a12b` | ✅ 4/4 | ✅ 4/4 | ✅ 4/4 | 4.1–4.3 с |
| `nvidia/nvidia-nemotron-nano-9b-v2` | ✅ 4/4 | ✅ 4/4 | ✅ 4/4 | 8.6–11.5 с |
| `openai/gpt-oss-20b` | ✅ 4/4 | ✅ 4/4 | ✅ 4/4 | 12.9–22.2 с |
| `nvidia/llama-3.3-nemotron-super-49b-v1.5` | ✅ 4/4 | ✅ 4/4 | ✅ 4/4 | 11.5–34.4 с |
| `z-ai/glm-5.2` | ✅ 4/4 | ✅ 4/4 | ⛔ HTTP 400 | 8.5–8.9 с |
| `meta/llama-3.3-70b-instruct` | 🟡 3/4 | 🟡 3/4 | ✅ 4/4 | 23.8–39.2 с |

**Решение:** использовать `response_format={"type":"json_schema"}` — работает
у всех кандидатов, не привязывает к расширению NVIDIA и переносится на другого
провайдера без переписывания.

## Раунд 3 — лимиты бесплатного тарифа

Ответ на вопрос «поможет ли новый API-ключ».

| Модель | Последовательно (12) | 8 параллельно (24) | 16 параллельно (40) |
|---|---|---|---|
| `nvidia/nemotron-3-super-120b-a12b` | **12/12**, p50 3.0 с | 10/24 | 0/40 |
| `nvidia/nvidia-nemotron-nano-9b-v2` | **12/12**, p50 5.8 с | 20/24 | 12/40 |
| `z-ai/glm-5.2` | 8/12 | 0/24 | 0/40 |

Все без исключения отказы — **HTTP 429 Too Many Requests**, то есть упор в лимит
ключа, а не нехватка мощностей провайдера. Ошибки `503 ResourceExhausted` и
`529 Overloaded` из первого раунда пришли только от моделей, которые мы не берём.

### Нужен ли новый ключ

**Для MVP — нет.**

Профиль одного пользователя — это последовательные запросы: человек пишет
сообщение, ждёт карточку подтверждения, отвечает. Восьми одновременных запросов
он не создаёт. В последовательном режиме основная модель отработала 12 из 12
без единой ошибки со средним временем 3 секунды.

Достаточно трёх вещей, которые всё равно нужны:

1. глобальный семафор на 1 одновременный запрос к NIM;
2. 3 ретрая с экспоненциальной задержкой на 429 и 5xx;
3. цепочка запасных моделей.

Заводить второй ключ имеет смысл только на фазе 2.6 второго роадмапа, когда
появятся другие пользователи. Учти при этом: 429 привязан к аккаунту, поэтому
второй ключ **того же аккаунта**, скорее всего, разделит ту же квоту —
независимый бюджет даст только отдельный аккаунт.

### Что это значит для отказоустойчивости

AI задействован **только на входе** — при разборе новых сообщений. В пути
доставки напоминаний модели нет вообще: tick-луп читает БД и отправляет сообщения.
Поэтому сбой NVIDIA означает «сейчас не могу разобрать фразу, повтори позже»,
но никогда — пропущенное собеседование.

Дополнительно без AI работают: все кнопки под уведомлениями
(`Выполнено` · `Через час` · `Перенести` · `Пропустить`) и частые текстовые ответы
вида «через 20 минут», «завтра», «уже сделал» — они разбираются регуляркой.

## Как перепроверить при смене модели

```bash
NVKEY=/path/to/key.txt python tools/bench_nvidia_ru.py
```

Прогонять при каждой смене основной модели и при заметном росте числа переспросов.
На фазе 2.5.6 второго роадмапа это становится регрессионным тестом.
