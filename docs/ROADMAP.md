# Roadmap Seshat

Roadmap разделён на два уровня: сначала надёжный персональный инструмент, затем
продуктовые возможности. Пункты второго уровня не считаются частью текущего MVP.

## Roadmap 1 — персональный MVP

| Этап | Результат | Статус |
|---|---|---|
| 0. Каркас | Python-проект, Compose, конфигурация, CI | ✅ |
| 1. Основа | PostgreSQL-схема, Alembic, domain и FastAPI | ✅ |
| 2. Создание | AI parsing, валидация, подтверждение, ручной fallback | ✅ |
| 3. Доставка | materialization, scheduler, quiet hours, timezones | ✅ |
| 4. Реакции | кнопки и контекст готовы; свободный текст в работе | 🟡 |
| 5. Обзор | «Мой день», списки, digest, review, статистика, editing | ⬜ |
| 6. Приёмка | семь дней без потерь и дублей, monitoring и restore check | ⬜ |
| 7. Calendar | односторонняя синхронизация разовых событий | ⬜ |

### Ближайший технический срез

1. Добавить детерминированный разбор частых ответов: «через 20 минут»,
   «завтра», «уже сделал».
2. Для остальных ответов использовать строгую LLM-схему с привязкой к активному
   уведомлению.
3. Гарантировать, что `unknown` ничего не меняет и приводит к уточнению.
4. Закрыть этап 4 unit-, API- и Telegram-contract тестами.

## Roadmap 2 — развитие в продукт

| Направление | Краткая цель |
|---|---|
| Гибкие рутины | нормы за период и перенос остатка без жёсткого расписания |
| Эффективность | объяснимые метрики, где числа считает код, а AI только формулирует вывод |
| Calendar 2-way | импорт, push updates, дедупликация и разрешение конфликтов |
| Планирование нагрузки | поиск свободных слотов и подтверждаемые предложения переноса |
| Зрелость | observability, rate limits, prompt-injection tests, regression evals |
| Multi-user | onboarding, пользовательский OAuth, экспорт и удаление данных |

## Правило готовности

Функция считается готовой только когда реализованы domain-правила, API-контракт,
Telegram-сценарий и автоматические проверки. Наличие кода без проверенного поведения
не закрывает этап.
